## UX / продуктовые скиллы — исследование (JEB-2029, 2026-10-31)

Главный вывод: **ни один скилл из исходного списка не закрывает генеративный UI**, то есть решения «текст или карточка, форма, ползунок, переход на страницу» и сокращение шагов в чате. Ближе всех подходят три скилла, которых в списке не было: kortix-genui, aiux-skills и CopilotKit. Свой скилл продуктового слоя придётся собирать в lab-forge из кусков. Готового решения нет.

Как читал: SKILL.md прочитан целиком у всех скиллов. Reference-файлы прочитаны целиком везде, кроме трёх больших репозиториев:

- design-for-ai: продуктовая часть (`ai-native`, `journey`), визуальная часть только по заголовкам;
- wondelai: продуктовая часть.

Токены посчитаны как слова × 1.3.

### 2. Топ-3

1. **kortix-genui.** Единственный скилл, который прямо отвечает на вопрос «когда рисовать блок, а когда писать текст».
   - Правила конкретные: «2–8 вариантов на выбор → стек карточек с фото»; «процесс из 4 и более шагов → блок steps»; «блок не нужен для фактов короче 3 предложений, объяснений и мнений без вариантов».
   - Для косметологии подходит напрямую: подбор средств = карточки с фото, протокол ухода = steps.
   - Минусы: только отображение, форм и ввода нет. Лицензия Elastic 2.0, поэтому правила пересказываем своими словами, а не копируем.
2. **szilu/ux-designer-skill.** Лучший из твоего списка. Грузит 1–3 reference-файла по задаче, так что в работе это примерно 5–10k токенов, а не 70k.
   - Полезное:
     - дерево решений «modal / side panel / full page» — основа для правила «карточка или переход»;
     - AI-паттерны: спектр suggest → auto-act с undo не меньше 10 секунд, формат ответа под тип вопроса, показ шагов агента;
     - правило «design every state»;
     - закон Теслера;
     - онбординг: максимум 1–2 вопроса для персонализации, профиль собирается постепенно.
   - Минус: много балласта (около 15k слов про штрихкоды) и цифры без источников.
3. **ryanthedev/design-for-ai, подмножество `ai-native` и `journey`.** Сильнее всех по IA и флоу: контракт цели, фиксированные якоря, «сужай пространство генерации», состояния флоу, шаблон спецификации страницы.
   - Минус: даже это подмножество занимает около 17k токенов. Берём выжимку.

Если брать строго из твоего списка, то по порядку: szilu, julianoczkowski IA (лёгкий, без визуала, 5 интервью-вопросов, шаблон карты страниц), civitai ux-design (шаблон четырёх состояний и спецификация экрана).

### 3. Рекомендуемая связка и порядок вызова

Ставить всё подряд не стоит: 38 + 111 скиллов из паков создают шум триггеров. Целевая схема такая: **один свой скилл `product-layer`, собранный в lab-forge, плюс твои визуальные скиллы.** Пока его нет, временная связка такая:

1. **IA и структура:** julianoczkowski IA. Определяет разделы, top tasks (5–10, каждая в пределах 3 кликов) и навигационную модель.
2. **Флоу:** use-case-схема из ThomasPraun. На каждом шаге задаём тест keep / cut / automate / hide и remove → default → defer → combine (cuellarfr и wondelai).
3. **Роутер генеративного UI:** правила kortix и aiux. Решают, что будет текстом, карточкой, формой, ползунком или переходом на страницу.
4. **Состояния и спецификация экрана:** civitai (idle / loading / success / error, точки входа и выхода).
5. **Визуал:** твои Apple Design, Taste и анимация.
6. **Ревью:** подсчёт steps-to-value, затем Vercel web-design-guidelines (зафиксировать версию правил локально, а не тянуть с main) и AccessLint.

Логика порядка: сначала решаем, **что** показывать и **где** (шаги 1–4), потом **как** это выглядит (шаг 5), потом проверяем (шаг 6). Визуальные скиллы не должны решать структуру.

### 4. Что взять в свой скилл (структура для lab-forge)

`SKILL.md` примерно на 1.5k токенов, в нём роутер по задачам. Остальное лежит в references и подгружается по требованию:

- **`genui-router.md`.** Ядро скилла, готового аналога нет.
  - Форма контента → блок, по kortix: 2–8 вариантов → карточки, сравнение → таблица, процесс → steps, всё короткое → текст.
  - «Отвечай сразу, предполагай типичный случай» (kortix).
  - «Кнопка, а не предложение» и «никакого пустого чата» (aiux).
  - Одна презентация на ход. Ползунок пересчитывает локально, агенту пишет только явная кнопка (CopilotKit, BuilderIO).
  - Каталог разрешённых компонентов, каждый — tool с описанием «когда использовать» (Google A2UI, Vercel AI SDK).
- **`card-vs-page.md`.** Склейка из:
  - дерева modal / panel / page (szilu);
  - таблицы «Modal vs Page» из styleseed;
  - разделения Tambo: компонент в чате или страница, которую AI обновляет;
  - правила cuellarfr: полностраничная форма, которой пользуются 10 раз в день, должна стать инлайн или оверлеем;
  - правила BuilderIO: разовый результат остаётся в чате, сохраняемый (протокол ухода) уходит на страницу.
- **`input-and-questionnaire.md`.** Этого нет ни у кого целиком.
  - Teslers-law: спрашивай только то, что знает только пользователь.
  - Один вопрос на карточку.
  - Чипы и ограниченные ползунки вместо числовых полей (cuellarfr).
  - `undefined` = «ещё не выбрал».
  - Квиз → рекомендация по сегменту (rampstack quiz).
  - Для анкеты кожи: фото вместо описания, где это возможно.
- **`flows.md`.**
  - Use case с пред- и постусловиями и альтернативными ветками, Mermaid не больше 15–20 узлов (ThomasPraun).
  - «Ни одного тупика», вход и выход у каждого флоу (ux-flow).
  - Steps-to-value и remove → default → defer → combine.
- **`ia.md`.** 5 интервью-вопросов, контент страниц с приоритетами, глоссарий названий (julianoczkowski). Top tasks, категории против тегов для каталога средств и проблем кожи (rampstack).
- **`states.md`.** Шаблон четырёх состояний и спецификация экрана (civitai), design every state (szilu), правила текстов ошибок и пустых экранов (frontend-design).
- **`trust.md`.** Доверие растёт поэтапно; пользователь видит, что приложение помнит, и может попросить забыть (Bencium relationship-design). Важно для истории кожи.
- **Формат.** Одно правило — один файл, пары «плохо / хорошо», рейтинг влияния (как в Vercel react-best-practices). Формат находок «серьёзность / уверенность / что не проверено» (AccessLint).

### 5. Лицензии и риски

- **kortix-genui (Elastic 2.0)** и **Shape of AI (CC-BY-NC-SA):** только пересказ своими словами, Shape of AI ещё и с атрибуцией.
- **borghei (Commons Clause):** не копировать.
- **AccessLint:** запускает непиннутый `npx @accesslint/mcp@latest` и делает `git stash` / `git checkout` в рабочем дереве.
- **UI/UX Pro Max:** в репозитории `settings.json` разрешает чтение всего `/home`. Не копировать.
- **Bencium controlled-ux-designer:** учит положительному `tabIndex`, это антипаттерн доступности.
- **ux-flow:** ссылается на файлы styleseed, которых в нём нет, поэтому вне styleseed агент может их выдумать.
- **Vercel web-design-guidelines:** тянет правила с `main` при каждом запуске. Зафиксировать копию.
- **Сырьё для `genui-router`:** Shape of AI (около 55 паттернов), Google PAIR Guidebook, Microsoft HAX (18 гайдлайнов как чек-лист аудита).

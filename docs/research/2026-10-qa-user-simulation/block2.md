# Блок 2. Open-source симуляция пользователей на LLM для UI-тестов (персоны, A/B)

Дата исследования: 2026-10-31. Контекст: генеративный UI в чате (карточки, кнопки, слайдеры, формы) плюс обычные страницы; пример — косметология (анкета кожи, подбор продуктов, протоколы ухода). Цель: прогнать сотни и тысячи персон, сделать A/B и найти места, где люди застревают.

Метод: GitHub API (`gh`), shallow clone UXAgent и TinyTroupe в локальный клон (код только читался, не запускался), arXiv, CEUR-WS, официальные страницы с ценами. Если код или цифру найти не удалось, это сказано прямо.

## 2. Заметки по каждому

**TinyTroupe** (https://github.com/microsoft/TinyTroupe, статья https://arxiv.org/abs/2507.09788). По умолчанию модель `gpt-5-mini`. Клиенты: OpenAI, Azure и Ollama (`tinytroupe/clients/`); нативного клиента Anthropic в коде нет. В v0.6.0 появился `SimulationExperimentEmpiricalValidator` для сравнения с реальными данными (t-тест, KS) и учёт стоимости. В v0.7.0 добавилась картинка как вход. Браузера и UI-действий нет. В нашем случае полезен для концепт-тестов и фокус-групп: «как 200 персон с разным типом кожи и бюджетом реагируют на протокол ухода». Найти, где пользователь застревает, он не поможет. В аннотации статьи упомянуты «preliminary experiments with real human behavior as control», но цифр на странице arXiv нет.

**UXAgent** (https://github.com/neuhai/UXAgent, https://arxiv.org/abs/2504.09407, CHI EA'25 https://doi.org/10.1145/3706599.3719729). Здесь есть всё, что нужно для массового прогона: `runConfig.yaml` задаёт `total_personas`, `concurrency`, взвешенную демографию, `example_persona`, `general_intent`, `max_steps` и анкету (SUS плюс свои вопросы). Есть Flask-бэкенд и React-UI мастера эксперимента. Результаты складываются в `runs/<timestamp>`: логи, трейсы, скриншоты, метрики. В коде `agent/gpt.py` модели такие: Claude Haiku 4.5 и Sonnet 4.5 через Bedrock, `claude-sonnet-4-20250514` напрямую; есть и вариант с Claude computer use (`computer_20250124`). Минусы:
- `parser.js` вырезает `svg`, `canvas`, `iframe`, `video` и оставляет только набор атрибутов плюс `aria-*`. Кастомные слайдеры и canvas-виджеты агент может не увидеть, поэтому в генеративном UI нужна нормальная семантика (`input[type=range]`, `role="slider"`, `aria-valuenow`).
- После каждого действия по умолчанию стоит `sleep_after_action: 2` и ожидание network idle. Это помогает при стриминге чата, но замедляет прогон.
- Каждая сессия съедает очень много токенов (см. AgentA/B ниже).
- 16 UX-исследователей в эвристической оценке хвалили новизну, но высказали сомнения. Авторы vizron ссылаются на то, что в UXAgent прогоны с персонами «were deemed unrealistic».

**AgentA/B** (https://arxiv.org/abs/2504.09723, v4 от 2026-03-10; Northeastern + Amazon). Это пока единственная известная мне работа, где симулированный A/B прямо сопоставлен с реальным A/B у людей. Кода нет: в статье написано «We will release our code upon acceptance», на GitHub по запросам «AgentA/B» и «agent-ab-testing» ничего релевантного нет. Методически это UXAgent плюс Claude 3.5 Sonnet и JSON-наблюдения. Цифры см. в разделе 4.

**SimAB** (https://arxiv.org/abs/2603.01024, Adobe Munich/Basel + ETH). На вход идут скриншоты вариантов, цель конверсии, опционально аудитория и документы. Персоны генерирует GPT-5-mini, голосует GPT-5. Персоны идут батчами по 5–10, прогон останавливается, как только результат значим (в примере значимость появилась после 31 агента). До 200 параллельных запросов, тест занимает «1–5 минут» (в разделе Limitations сказано «2–10 минут»). Денежная стоимость в статье не указана. Кода и репозитория я не нашёл: искал по GitHub и в вебе. Метод очень простой, его легко воспроизвести в своём скилле. Для генеративного UI это подходит как дешёвый пре-скрининг статичных вариантов карточек или экранов. Интерактивность, стриминг и многошаговые сценарии метод не покрывает: авторы сами называют это ограничением.

**vizron** (https://ceur-ws.org/Vol-4249/paper5.pdf, https://www.wi.uni-muenster.de/publication/197555912). Это 6-страничная позиционная статья для CHI'26 Workshop on Responsible Use of AI Personas. Кода нет: ссылки в статье нет, поиск по GitHub «vizron» ничего не дал. Метрик и сравнения с людьми тоже нет. Главный практический вывод: системный промпт Browser-Use, заточенный на эффективное достижение цели, конфликтует с персоной. Например, «пожилая» персона в think-aloud жалуется на мелкий шрифт, а агент всё равно проходит сценарий идеально. Авторы предлагают разделить роли: персона-LLM решает, что сделать дальше, а Browser-Use только исполняет. Если строить на Browser-Use свой движок, этот урок нужно учесть с самого начала.

**Browser-Use** (https://github.com/browser-use/browser-use, цены https://browser-use.com/pricing).
- **OSS:** библиотека на Python, работает с любой LLM, включая Claude.
- **Cloud:** браузер стоит $0.02 в час, у хостингового агента наценка 20% на модель. Их модель BU 2.0 стоит $0.60 / $0.06 (кэш) / $3.50 за 1M токенов. Лимит параллельных сессий растёт с суммой оплаты: от 10 при $0 до 1000 при $25k.
- **Скорость** по их блогу (https://browser-use.com/posts/speed-matters): около 3 с на шаг, BU 1.0 тратит около 68 с на задачу OnlineMind2Web против 285 с у Claude Sonnet 4.5. Это данные вендора.
- **Бенчмарк BU_Bench_v2** на странице цен: $/задачу от $0.056 до $8.9. Задачи там длинные исследовательские (5–36 минут), так что на 15-шаговую UX-сессию эти цифры не переносятся.
- **Персон и UX-отчётов нет**, всё это нужно писать самим. Зато это лучший фундамент для своего движка: MIT, огромное сообщество, кастомные действия (можно добавить «пауза / растерянность / отказ»), облако для масштаба.

**humanish** (https://github.com/danielgwilson/humanish, стоимость https://humanish.dev/docs/what-a-study-costs). По качеству доказательств лучший из найденных: видео и скриншоты, трасса действий с рассуждением, находки со ссылками на моменты, `verify`, лимиты бюджета. Работает через computer use: OpenAI или `claude-haiku-5-5`, на E2B-десктопах или локальной VM; анализ по умолчанию делает OpenAI. Измеренная стоимость:
- **один участник** — $0.13–1.10;
- **десктоп** — $0.009 в минуту;
- **6 участников по 10 минут** — около $3–20.

Проект молодой (15★). Подходит для качественных исследований на 5–20 персонах, не для тысяч.

**Avenir-UX** (https://github.com/Onflow-AI/Avenir-UX, https://arxiv.org/abs/2604.09581). Протокол SUS + SEQ + think-aloud, персона из TOML, ключи через OpenRouter. Сравнения с людьми на странице arXiv нет. Лицензия формально не оформлена: бейдж есть, LICENSE-файла нет.

**Stagehand / Skyvern / Magnitude.** Это движки браузерной автоматизации, слоя персон и UX у них нет. Stagehand (MIT) удобен, если основной стек на TypeScript. Skyvern под AGPL-3.0, для встраивания в продукт это риск. Magnitude (Apache-2.0) идёт от vision и имеет тест-раннер; хорош для детерминированных проверок «кнопка видна / нажимается».

**Claude computer/browser toolset.** На странице цен Anthropic (https://platform.claude.com/docs/en/about-claude/pricing) описаны `browser_toolset_20260801` (около 6.6k входных токенов на определение, кэшируемо) и `computer_toolset_20260801` (около 4.5k). Скриншоты оплачиваются как image input. Это нативный путь для своего скилла без сторонних фреймворков, но цикл агента, персоны и отчёт придётся писать самим.

**Другие найденные работы:** SUTM (https://ceur-ws.org/Vol-4249/paper4.pdf, кода нет), AMUSER (https://arxiv.org/abs/2609.22971, кода не нашёл), uxCUA (https://arxiv.org/abs/2604.26020, кода не нашёл), PAARS от Amazon (https://www.amazon.science/publications/paars-persona-aligned-agentic-retail-shoppers), Data-Driven Persona-Conditioned Agents (https://arxiv.org/abs/2609.01038, EMNLP 2026 Industry), OPeRA dataset (https://arxiv.org/abs/2506.05606). OpenAI CUA sample app (https://github.com/openai/openai-cua-sample-app, MIT) я детально не разбирал: цены на CUA-модель на странице OpenAI не нашёл.

## 4. Что говорит наука о поведенческом реализме

1. **AgentA/B** (https://arxiv.org/html/2504.09723v4): 100,000 сгенерированных персон, из них 1,000 сессий (по 500 на вариант) против реального теста Amazon с примерно 1–2M людей (в тексте 2M, в таблице 1M).
   - Агенты купили 403 раза в control и 414 в treatment, χ²(1)=5.51, p=0.03. Средний чек $55.14 против $60.99, разница незначима.
   - Совпадение с людьми только по **направлению эффекта**, формальной метрики согласия нет.
   - Агенты гораздо «прямолинейнее» людей:
     - действий за сессию: 6.05–6.60 у агентов против 15.96 у людей;
     - кликов по товарам: 1.87–2.09 против 6.96;
     - поисков: 1.42–1.43 против 6.40.
2. **SimAB** (https://arxiv.org/html/2603.01024): на 47 исторических A/B-тестах точность угадывания победителя **67%** (precision 71%, recall 79%). В высокоуверенных случаях точность **75%** в тексте статьи, а в аннотации указано 83% — несоответствие внутри самой статьи. Без разнообразия персон (одна фиксированная персона) согласие падает на **10 п.п.** Модель предсказывает только победителя, величину эффекта нет.
3. **Data-Driven Persona-Conditioned Agents** (https://arxiv.org/abs/2609.01038): 40 A/B-тестов, направленная точность **0.75–0.80**. Персоны построены из реальных поведенческих данных.
4. **«Can LLM Agents Simulate Multi-Turn Human Behavior?»** (ACL 2026, https://arxiv.org/abs/2503.20749): на 31,865 реальных сессиях и 230,965 действиях LLM с одними промптами (DeepSeek-R1, Llama, Claude) угадывают следующее действие человека в **11.86%** случаев. Дообученный Qwen2.5-7B даёт 17.26%, F1 покупки 33.86%. Вывод: на уровне отдельного человека поведение не воспроизводится, на уровне агрегатов и направлений иногда воспроизводится.
5. **Park et al.** (https://arxiv.org/abs/2411.10109): агенты, построенные по 2-часовым интервью с 1,052 людьми, воспроизводят ответы GSS на **86%** от тест-ретест-согласованности самих людей. Агенты только на демографии дают **74%**. То есть персоны из одних демографических полей заметно слабее.
6. **Мега-исследование цифровых двойников Twin-2K-500** (https://arxiv.org/html/2509.19088v4): 19 исследований, 164 исхода. Индивидуальная точность около 75%, но корреляция с людьми слабая (**r≈0.20**). Найдены 5 систематических искажений: недостаточная индивидуализация, стереотипы, репрезентативный и идеологический сдвиги, **гиперрациональность**.
7. **Hewitt, Ashokkumar et al.** (https://ai4pb.stanford.edu/projects/predicting-results-of-social-science-experiments-using-large-language-models): GPT-4 предсказывает эффекты 70 опросных экспериментов с **r=0.85**, на неопубликованных r=0.90, но **завышает величину эффектов** (по комментариям, примерно вдвое).
8. **SimUser, CHI'24** (https://doi.org/10.1145/3613904.3642481): совпадение с обратной связью 48 реальных пользователей составило от **35.7% до 100%** в зависимости от группы и категории.
9. **SUTM** (https://ceur-ws.org/Vol-4249/paper4.pdf): агент-супервизор поднимает precision диагнозов по ISO с 0.75 до 0.91 и снижает непоследовательность персон с 45% до 0.8% на 45 прототипах.
10. **NN/g** (https://www.nngroup.com/articles/synthetic-users/): синтетические пользователи слишком позитивны и идеализированы. Пример: агент «прошёл все курсы», а реальные пользователи бросали на середине. Использовать их стоит для гипотез, а не для валидации.
11. **vizron**: персона в промпте Browser-Use почти не меняет путь навигации, то есть разнообразие персон оказывается иллюзией.

**Итог по реализму.**
- **Работает:** направление A/B-эффекта на агрегатах (67–80%) и поиск грубых юзабилити-проблем.
- **Не работает:** величина эффекта, точный путь конкретного человека (около 12%), «застревания» из-за терпения, усталости или недоверия. Агенты гиперрациональны и делают в 2–3 раза меньше действий.
- **Значит, нужно:** (а) персоны из реальных данных, а не только из демографии; (б) отделить «решение персоны» от «исполнителя» (урок vizron); (в) явно моделировать бюджет терпения и вероятность отказа; (г) калибровать на 1–2 реальных A/B-тестах; (д) считать результатом направление и список проблем, а не конверсию.

## 5. Рекомендации для генеративного чат-UI (косметология)

1. **Чат-UI можно симулировать на уровне протокола, без браузера.** Генеративный UI и так приходит в клиент как JSON-спека компонентов (карточка, кнопки, слайдер, форма). Агенту-персоне можно отдавать эту спеку как текст или как отрисованный скриншот, а его действия возвращать через ту же схему событий. Это в 10–50 раз дешевле браузера, детерминировано и масштабируется до десятков тысяч прогонов. Браузер нужен для проверки вёрстки и для обычных страниц. Это мой вывод, исследований именно про это я не нашёл.
2. **Для DOM-агентов нужна семантика.** Слайдеры должны быть `input[type=range]` или `role="slider"` с `aria-valuenow`. Нужен маркер «стрим завершён» (например, `aria-busy=false` на сообщении), иначе агент кликает по недорисованному UI. Без этого UXAgent и Browser-Use теряют кастомные виджеты, потому что парсер UXAgent вырезает `svg` и `canvas`.
3. **Модели:** исполнять шаги дешёвой моделью (Haiku 5.5, Flash-Lite, gpt-5-mini), а решения персоны и итоговый отчёт делать сильной (Sonnet 5.5). Задачи без интерактива отправлять через Batch API.

## 6. Топ-3 для массовой симуляции

1. **Свой движок в Claude-скилле на Browser-Use (MIT) с идеями UXAgent.** Сэмплер персон, анкета SUS и SEQ, архитектура vizron «персона решает, исполнитель кликает», модель терпения и отказа. Цена около $2–60 за 1000 сессий на дешёвых моделях. Масштаб через Browser-Use Cloud. Плюс режим протокольной симуляции для генеративного UI.
2. **UXAgent как готовая основа и референс.** Batch-режим с демографией, параллельностью и анкетами есть из коробки, Claude поддерживается, MIT. Методика проверена на 1000 сессий в AgentA/B. Минусы: дорогие «толстые» сессии (около $2/сессию на Sonnet; на Haiku 5.5 около $0.1) и DOM-парсер, который нужно адаптировать под генеративный UI.
3. **SimAB-подобный пре-скрининг вариантов по скриншотам** (своя реализация: кода нет, метод простой). Около $7–13 за 1000 персон с batch. 67–75% точности угадывания победителя на реальных тестах. Подходит для быстрого отсева вариантов карточек и экранов до дорогих интерактивных прогонов.

Для глубокого качественного разбора на 5–20 персонах с видео и доказательствами лучше всего **humanish** (MIT). Для концепт-тестов и фокус-групп без UI подходит **TinyTroupe**.
